# Error LX004: Unescaped Bidirectional Unicode Character (Trojan Source)

This error occurs when a source file contains unescaped bidirectional (BiDi) Unicode control characters (such as Left-to-Right Embedding, Right-to-Left Override, or directional isolates) in comments, doc-comments, strings, or code.

## Erroneous Code Example

```arandu
// Check if user is admin ‮ } return true; /*
func is_admin(user: User): bool {
    return false
}
```

## Semantic Explanation

Bidirectional Unicode control characters (such as `U+202E` RLO, `U+202A` LRE, `U+2066` LRI, etc.) alter the visual rendering order of text in code editors and diff tools without changing the logical character order parsed by the compiler.

This mismatch creates the **Trojan Source** vulnerability (CVE-2021-42574, CWE-1307), enabling an attacker to visually disguise malicious executable statements as harmless comments or vice-versa. To ensure source code determinism and protect code reviews, Arandu strictly prohibits unescaped BiDi formatting characters in source files.

## How to Fix

Remove the invisible bidirectional control character. If the character is genuinely required inside a string literal, use an explicit Unicode escape sequence:

```arandu
let bidi_string = "\u{202E}" // ok: explicit escape is visible and safe
```
